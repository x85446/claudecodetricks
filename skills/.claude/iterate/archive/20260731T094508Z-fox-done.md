## Constraints
- **macOS 26 arm64 (Apple Silicon).** Emulator system image must be `arm64-v8a`; Rosetta x86_64 is fallback only.
- **Shell is bash** (`/opt/homebrew/bin/bash`), rc file is `~/.bashrc`. Do NOT touch `~/.zshrc`.
- **No global JAVA_HOME change.** User's default JDK stays at Temurin 26 for other work; JDK 21 is scoped per-project via `gradle.properties`.
- **No git remote yet on androidready** — Step 7/14 "merge" is local fast-forward, not a PR/MR. Push later when a remote is configured. personaldb likely has a remote — respect its /feature-branch flow (PR/MR if a remote exists).
- **Homebrew casks may prompt for sudo** on Temurin 21 install; if that stalls, surface as a giveup so the user can approve interactively.
- **+5–6 GB disk** for SDK + system image + Rust build artifacts + Gradle deps. Assumed available.
- **Emulator first-boot 60–120s** — poll `sys.boot_completed`, don't fixed-sleep.
- **Financial data exposure — bind to Tailscale (`100.96.0.23`), never `0.0.0.0`.** Token auth required on every endpoint. No CORS wildcards. Do NOT publish port 8012 to the public internet.
- **Context: SQLite single-writer rule** (from personaldb CLAUDE.md). While the HTTP server has a write connection open to `db/personaldb.sqlite`, the macOS host app and the lume VM app MUST be quit — same rule as host↔VM already. Oracle "iterate app lifecycle" grants standing permission to quit/relaunch both during this iterate run.
- **Context: bulk write target** (oracle: main database writes). The server writes to `db/personaldb.sqlite` (default via `PERSONALDB_DB` unset). Do NOT let the server target a backup or the VM copy. Log the resolved write path at server startup (validated in 8).
- **Context: Rust core layout.** All existing FFI at `native/personaldb-core/src/lib.rs` and the Swift-facing exports stay untouched. The new HTTP server is a NEW binary target that reuses the same queries — additive only. No `make app` in unattended contexts (it steals desktop focus).
- **Context: emulator → cypressMini reachability.** Android emulator uses host network via NAT (`10.0.2.2` is the host from inside the emulator); to reach cypressMini's Tailscale IP (`100.96.0.23`) the host must have Tailscale up AND the emulator must forward to it. If direct Tailscale IP fails, fall back to the host's LAN IP (`192.168.144.203:8012`) or `10.0.2.2:8012` and update the app's default base URL accordingly.
- **No reboots of cypressMini are allowed during this run.** All steps must be doable in the live macOS session — no `shutdown -r`, no `reboot`, no `sudo reboot`, no OS updates that require a restart. Kernel extensions, drivers, or SDK components that would demand a restart are out of scope. Emulator lifecycle (create/boot/kill AVD) is fine — those are user-space processes. If a step's natural remedy would be "just reboot the Mac," treat it as blocked and log alternatives (kill offending process, reload launchd job, unload/reload kext without reboot, defer install) rather than restarting.
- **CRD keepalive daemon** (`com.travis.crd-keepalive`) is unaffected by this work and stays running in the background throughout.
