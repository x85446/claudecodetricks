# Conductor engine

`Service` owns configuration, decisions, assignments and durable progress. `NewService(dir, source)` selects an isolated state directory and an injected plan adapter. `iterrun.NewConductorService` supplies the repository's Markdown plan adapter. The default directory is `~/.claude/iterate/conductor`; `ITERATE_CONDUCTOR_DIR` selects another store.

`Config`, `Apply`, `ValidateDraft` and `Migrate` provide revisioned configuration. A process-safe lock serializes transactions. Configuration uses synced temporary files and atomic replacement. Universal remains editable and required. Disabled incomplete Custom CLI definitions remain editable but cannot dispatch. Canonical project folders and scoped references prevent basename collisions. Migration preserves a source backup and converts remaining targets into percent used once.

`Evaluate` is read-only. It accepts an optional draft, project/automation filter, common sample time, usage and account sample controls. Samples never write configuration, occurrences, usage or plans. Saved subscription and overdrive enable switches remain authoritative. `BudgetPreview`, `OverdriveOptionsFor` and `OutsideOverdriveTime` use the same budget/recurrence implementation. `Queue` reports exact waiting plan identities and separates active manual or supervisor assignments.

`PreviewOverdriveConversion` derives a subscription-owned reset-relative hour offset from fresh, account-bound trusted allowance evidence. Its read-only preview preserves the current interval’s start, reset, window identity, target and enablement. Save uses the returned configuration revision. Ordinary independent-end windows, multiple selected days and multiweek recurrences cannot convert without losing timing and are rejected. Each subscription derives its own offset; future DST or provider-reset changes follow that fixed duration rather than a fixed civil start.

`Tick` and `TickProject` refresh authenticated allowance evidence, reconcile prior workers, evaluate gates and atomically claim one bounded assignment. The store lock is released before executing the literal argument vector. Workers run independently of HTTP requests. Their owner PID/start identity, child PID/start identity and immutable assignment snapshot persist before execution. `ControlExpected` supports revision-checked lifecycle writes. Pause and stop prevent subsequent assignments; kill signals only owned processes.

A `PlanSource` supplies queue summaries, dependency-ready pairs, legacy policy gates and checkpoint writes. The Markdown adapter preserves plan identity and validation evidence, consumes staged authorization at claim, writes a fresh run marker, and checks task/validation digests before checking both boxes. Repeated checkpoints and delivery archival reconcile by assignment identity. A source's `OutcomeSource` handles verified delivery, partial landing and issue-plan provenance. A source's `LeaseSource` maintains legacy run markers.

The supervisor drains managed stdout and stderr pipes concurrently into mode-0600 logs. Structured stdout passes through provider normalization; generic diagnostics remain in restricted logs. Records are bounded at 1 MiB, each raw log at 64 MiB, and public history retains approximately 10,000 events per run. Append records are synced before publication; the dedupe index checkpoints every 128 events and rebuilds from durable records after interruption. A storage failure prevents success. Final output and a matching versioned result precede any checkpoint advancement. An executor leaving descendants receives a retry outcome after owned cleanup.

`Events` returns at most 500 records strictly after a cursor, indicates expired cursors and reports execution tokens separately from subscription allowances. Stable provider IDs reconcile duplicate observations. Claude stream and hooks share tool IDs; assistant usage remains separate. Codex stream IDs and hook IDs lack a verified common identity, so its stream owns public tool activity while the existing hook trace remains separate. Public events omit raw tool payloads and redact common credential forms.

Interrupted work requires bounded diagnosis with its original sequence before profile handoff. Retry accounting is per failing state, with a five-attempt default and a 45-minute no-progress bound. A new checkpoint receives its no-progress interval at admission after validated advancement; gated idle time between completed checkpoints does not consume it. Retries of the same incomplete checkpoint retain their elapsed budget. Partial results route to a separate delivery assignment; unfinished work remains parked with evidence. Idle watches use no AI, reach a configurable stood-down state and reactivate when work becomes eligible. Notices and issue intake have durable keys. Opted-in intake reads issues through installed `gh` or `glab`, caps batches, and asks a bounded assignment to create an unstaged plan with source provenance. It never mutates remote issue state.

The process supervisor supports Unix process groups and advisory locks. Unsupported ownership primitives fail closed. Tests inject clocks and allowance collectors into isolated stores and spawn actual fixture processes. Live account authorization, installed-server behavior and web interaction remain separate acceptance evidence.
