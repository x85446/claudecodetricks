## Constraints
- Context: the dashboard's project index is `~/.claude/iterate-run/projects.json`, written by `RegisterProject` only for directories that already have `.claude/iterate/plans/` — discovery is not a filesystem scan, so a Codex-only project appears exactly when it first gets a plan.
- Context: both harnesses already write the same `./.claude/iterate/` state paths. The gap this plan closes is that nothing records WHICH harness wrote a plan, not that the paths diverge.
- Context: Codex frontmatter permits only `name` and `description`, which is why the ports carry their version as a body line. Any field this plan adds to a Codex-side plan file is written by the skill body, never by port frontmatter.
- Naming: launchd labels follow the existing `com.x85446.<service>` convention set by `com.x85446.codex-skill-sync`.
- Oracle (app data locations): on macOS, Go's `os.UserCacheDir()` and friends do not cover logs or runtime state. New artifacts follow the Apple convention — logs to `~/Library/Logs/iterate-run/`, pid and port files to `$TMPDIR`. Existing state stays at `~/.claude/iterate-run/`; this plan does not migrate it.
- License: Google Chrome — proprietary, run as an installed application, never linked or redistributed. Chromium (BSD-3-Clause) is the permissive equivalent and the agent must accept a `CHROME_BIN` override so it can be pointed at Chromium or any Chromium-family browser without editing the plist.
- Cost: none — every component is already installed or free: launchd is the OS, Chrome is installed, and no step adds a paid service or a metered account.
- The animal pool floor is 12 per letter, not a flat multiple of each letter's current count. A uniform multiple leaves `u` and `x` at 12 while taking `a` to 72, and the scarcest letter is what actually caps a project's plan count.
- macOS only for steps 9 and 10. launchd is not portable; the make targets must fail with a clear message on other platforms rather than half-installing.
