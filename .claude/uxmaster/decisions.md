# UX decisions

- 2026-10-16: Conductor Settings retains its header utility and left navigation. Editors use bounded widths; collection Add actions sit beside headings, item Edit actions sit beside names, and overdrive metadata and editor actions stay grouped with their window. This keeps short content and its controls together on wide displays.

- 2026-10-16: Configuration collections use draft-only Add/Edit dialogs with Save-to-commit-and-close, Cancel/Close/Escape-to-discard, keyboard focus containment and return focus. Breadcrumbs retain parent identity; browser and application Back restore prior locations; Settings returns to its entry page with automation drafts intact. Shared definitions expose usage and reject invalid deletion atomically.

- 2026-10-16: Subscription panels share one 800px boundary. Named-definition rows group Duplicate, Delete, Edit beside the name and Add beside the section heading. Overdrive rows show the name and used target percentage on one line; dialogs contain schedule details and preserve underlying page scroll on opening and closing.

- 2026-10-16: Duplicate and Delete use text-link styling on semantic buttons across collections, selectors and dialogs. Edit and Add use outlined buttons. Mouse hover adds an underline to links and accent feedback to buttons without changing their geometry; keyboard focus remains visible.

- 2026-10-16: Named Power Bands form a shared definition collection. Each subscription selects exactly one, defaulting to editable Universal power band. The editor exposes assigned subscriptions and an unsaved-draft simulator; referenced deletion requires reassignment.

- 2026-10-16: Projects anchor the portal. All projects opens a project workspace with Plans, Automations and Activity. Queued, active and archived plans share the Plans tab; queue counts deep-link into the selected project. Settings remains global and returns to the originating project tab.

- 2026-10-16: Preview 24 uses compact rows across plans, automations, activity and settings collections; project tabs share a 1000px width, settings retain 800px panels, and editors and simulators retain comfortable spacing.

- 2026-10-16: All projects uses a six-column sortable semantic table. Tags live in revisioned project configuration; multiple filters match any tag and persist alongside sorting in the URL. Enrolled identifies configuration ownership independently of enablement. Planned excludes queued/running plans. Activity links to the recorded plan milestone or assignment activity. Native Chrome verification covers sort toggles, tag save/reload/edit, OR/empty filters, plan drill-down, browser Back and a 320px viewport with table-contained scrolling.

- 2026-10-16: Plan views use All, Draft, Queued, Running, Blocked and Archived with one exclusive state per plan. All shows blocked work first; the project overview counts Blocked separately from Draft and Queued. Short badges, wrapped expandable reasons and a compact grid keep long operator messages inside the panel. Native Chrome verifies Filemaster counts 41/0/23/0/2/16, keyboard expansion and a 320px viewport without page overflow. The scheduler permits other eligible queued work while a plan is blocked; cross-plan prose dependencies are not enforced.

- 2026-10-20: AI subscription setup follows AI tool, installed executable, account/usage status and named power band in one compact dialog. Required and optional labels describe user choices; provider-owned transport and bindings remain automatic with read-only diagnostics. A resolved host path and Verify installation distinguish discovery from account readiness. Custom command arguments use literal argument rows and a command preview; collector and result-contract controls appear only when customization requires them. Models, reasoning and permissions belong to Named Launch Sequences. Provider switching reconciles dependent defaults, preserves explicit edits without silently making incompatible combinations, and invalidates stale readiness. The subscription summary owns the Enable/Disable switch; account checks do not enable or launch work. Context help uses keyboard- and touch-accessible (i) popovers. These are design decisions for javelina; no live UI audit or implementation is claimed.

- Running plan badges name the current execution owner, Conductor or CLI, from the binary queue ownership response. Historical run records do not establish current ownership; tool labels remain separate.
- 2026-10-21: Plan detail hierarchy places project navigation first, plan identity/goal/progress second, and Conductor activity beneath the summary. A keyboard-focusable 260px event scroller and native disclosures keep logs and usage observations contained. Verified on live Caiman: header order, collapse/expand, independent scroll extent, and keyboard Home; detail preservation and identity tests pass. Existing Codex worker PID 32344 survives installation.
- 2026-10-22 (killdeer): The automation editor is a URL state (`automation=<id>|new`) inside Settings and the project Automations tab; the rail link and tab always show the list. Unsaved drafts are kept per automation ID in session storage, listed as "Unsaved draft" rows with Resume and Discard, and labelled in the editor beside the saved name. Save rebases onto the newest revision when that automation and its window are unchanged; a true conflict reports beside Save.
- 2026-10-22 (killdeer): The automation tester evaluates draft rows for a hypothetical eligible project. Inputs are the automation's own rules only: one sample band (radio group), the sample day and hour for schedules, and the subscription-overdrive state when the rules honor it; overdrive mode keeps its window and used-percent samples. It shows one outcome in a polite live region and a per-band summary (Green, Yellow, Red → first row that launches, or why it waits). Project, plan, lease, executable, account and conductor state never enter it; production admission keeps them.
- 2026-10-22 (killdeer): Project Associations is a Settings section with two orientations (by automation, by project). Dragging a project onto an automation attaches it disabled; dragging an attached chip to the palette detaches it. WCAG 2.2 SC 2.5.7 requires a single-pointer path, so every card has an Attach select and button and every association a Detach button and an Enabled switch. Results are announced in a status region; failures re-read the saved configuration and say what was kept.
- 2026-10-22 (killdeer integrity): The plan report leads with Verified progress: the plan outcome (lifecycle state, status line, completion and archive events with provenance, merge reference) sits above any count, and requirement, lane and attempt counts each name their unit. A coordinator lane closes with the plan's completion event; a team lane closes on its Teams table status or its log's TEAM DONE/BLOCKED line; in an ended plan a lane with neither is "Unknown end", never queued or running. Attempt counts with no recorded attempt read "unknown", not zero.
- 2026-10-22 (killdeer integrity): Requirement state reads checkboxes first. A team report or plan-log claim can raise a requirement (unboxed plans, a team ahead of the coordinator) but never lowers a checked box; the claim appears as imported evidence instead.
- 2026-10-22 (killdeer integrity): Validation evidence is one native disclosure per requirement, linked from progress by #evidence-req-N (a small inline script opens the target). Acceptance text has its own disclosure. Observed items and imported prose are labelled apart; imported prose keeps result "not observed" and shows its claim as "Reports: …" plus extracted figures (test counts, exit status, hashes, merge PRs). Plan-log lines split at each step mention; text naming no requirement is plan-level evidence. Earlier attempts and superseded team reports stay listed. Freshness compares a proof's revision with the working tree over its covered files (git diff with GIT_OPTIONAL_LOCKS=0); stale proof stays listed with the changed files named.
- 2026-10-22 (killdeer accounting): Report state badges are words on a tinted background with the state color as the border, never colored text alone; complete/partial/unavailable sections never disappear, an unknown figure renders as "unknown" and a lower bound as "partial". Tables carry explicit ARIA roles and become labelled cards below 600px.
